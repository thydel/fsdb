## Proposal for Repository Restructuring & Document Structure

To maintain full project context and expertise after splitting private logs from public code:

1. **`docs/architecture.md`**: Detail the schema specifications, partition design (e.g., handling server columns), and DuckDB/M4/Bash pipeline compilation model.
2. **`docs/cte-reference.md`**: A detailed spec sheet for each pipeline operator, its parameters, inputs/outputs, and DuckDB translations.
3. **`docs/testing-ingestion.md`**: Document target schemas, expected outputs, and step-by-step instructions for local test suite execution.
4. Keep the `CLAUDE.md` and the `skills/` files in the public repository. These files are public-facing but provide critical instructions to maintain agent execution fidelity.

## Pertinence of a Dedicated `fsdb-cte` Skill

A dedicated `skills/fsdb-cte/SKILL.md` is highly pertinent. It should enforce:
- Composing pipeline queries using the DuckDB SQL dialect (e.g., `list_slice()`, `unnest()`, array operations).
- Adhering to the "channel pattern" for `baj` macros (propagating aliases for `ts`, `file`, `tbl`, `vals`, `part` to ensure composability).
- Rules for writing composable, parameterizable CTEs (no defaults for `start` dates, using a channel to propagate configs).

## Difficulty and Complexity of a Better `stat(1)` Ingestion

Parsing raw `stat(1)` outputs via custom string logic is brittle on complex file trees with arbitrary names (spaces, quotes, or newlines).

- **Difficulty**: Low to Medium.
- **Proposed Solution**: 
  - Write a helper script (`scripts/stat-to-json.py`) that walks directories and calls `os.lstat` or `os.stat` to format findings directly into structured JSON lines.
  - Load the resulting JSON directly into DuckDB using `read_json_auto`, bypassing fragile Bash text formatting pipelines.

## Rethought CTE Organization & Testing

- **Composable Primitives**:
  - `since <ts>` & `until <ts>`: Pure date filters.
  - `slice <start> <end>`: Native path trimming using `list_slice`.
  - `aggregate [path|server]` or `sum [path]`: Group-by operations with flexible grouping columns.
  - `growth <pivot_date> [--col=size] [--active]`: Returns start, growth, end, rate; `--active` appends a `HAVING <col>_growth > 0` clause.
  - `limit <n>`: Truncation.
- **Parameter Validation**:
  - Remove default values from temporal boundaries in commands like `growth` or `since`. Raise explicit compile-time errors in `baj` if parameters are missing.
- **Testing Architecture**:
  - Create a static test tree under `test/fixtures/cpython-v3.14.5`.
  - Build `test/fixtures/cpython.db` via the build script.
  - Write test assertions (e.g., comparing pipeline query outputs against fixed target CSVs).
  - Create a shell test suite script (`test/run.sh`) run via the `Makefile`.
