### 2. Examples of `cumul` without `-p none` (with partitioning)

Partitioning is essential when you have multiple categories (servers, base
directories, or file owners) in the dataset and want to compute the running sum
**independently** for each category.

#### Example A: Server-by-Server Cumulative Growth

If you do not aggregate the servers first, `cumul` will default to partitioning
by `server` (since `start` initializes `$_a.part = "server"`):

``` bash
start | span month | cumul | plot-ddb
```

This computes the cumulative growth curves independently for each server. If you
have `server1` and `server2`, their rows will be accumulated separately:

-   `server1` rows accumulate into `server1`'s running total.
-   `server2` rows accumulate into `server2`'s running total. Without
    partitioning, the rows would interleave and sum across servers, corrupting
    individual server history.

#### Example B: Directory-by-Directory Cumulative Growth

To see the cumulative growth of each main site/directory separately:

``` bash
start | span --group=path[1] month | cumul -p path[1]
```

This partitions the cumulative sum by the top-level directory `path[1]`, giving
the historical growth curve of each directory individually.

### 4. CTE Assessment and Proposed Missing Operators

The current CTE set is highly capable for filtering, grouping, and computing
running totals. To build a comprehensive capacity prediction system, I propose
adding the following missing operators to the library:

#### A. `fill` (Time-Series Densification)

-   **Goal:** Natively fill missing time buckets with zero deltas in DuckDB.
-   **Why:** Essential when comparing or aggregating cumulative growth curves
    across multiple directories or servers where changes happen in different
    time buckets.
-   **Proposed SQL:**
    ``` sql
    WITH grid AS (
      SELECT *
      FROM (SELECT generate_series AS date FROM generate_series((SELECT MIN(date) FROM {prev}), (SELECT MAX(date) FROM {prev}), INTERVAL '1 hour'))
      CROSS JOIN (SELECT DISTINCT server, path FROM {prev})
    )
    SELECT grid.date, grid.server, grid.path, COALESCE(actual.cnt, 0) AS cnt, COALESCE(actual.size, 0) AS size
    FROM grid LEFT JOIN {prev} actual ON grid.date = actual.date AND grid.server = actual.server AND grid.path = actual.path
    ```

#### B. `forecast` (Linear Regression to Capacity Ceiling)

-   **Goal:** Run linear regression on the cumulative size to estimate when the
    filesystem will hit a given ceiling (TTF - Time To Full).
-   **Why:** Instead of guessing the slope, let DuckDB calculate
    `regr_slope(size, date)` and `regr_intercept(size, date)` over a historical
    window to project the exact date when `size >= capacity`.
-   **Proposed Signature:** `forecast --cap=<size_bytes> --window=<interval>`
